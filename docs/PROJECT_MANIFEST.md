# Project governance manifest

- Product/repository identity: `x-patentsar` / X-PatentSAR; current stable E-drive WSL source path `/srv/wsl/projects/patent-sar-extractor` (preserved through branding). Internal Python namespace remains `patent_sar_extractor`; it is not a competing product identity.
- Product version authority: `src/patent_sar_extractor/contracts.py`; current release `v0.1.0`; Semantic Versioning; release tags use `vMAJOR.MINOR.PATCH`.
- Internal contract authority: the same `contracts.py` file separately owns pipeline contract `2.0.0`, ruleset `2.0.3`, stage implementation epochs and artifact/cache/observation schema identities.
- Supported source roots: `src/patent_sar_extractor`, `frontend`, `tools`, `examples`, `docs`, `tests`, `.github` and documented root metadata/launch files, including Apache-2.0 `LICENSE` and attribution `NOTICE`. `tools` owns reproducible build/packaging checks, not extraction logic.
- Dependency authority: `pyproject.toml` plus generated `uv.lock`; uv 0.11.31 is the verified lock/sync tool, matching CI. The `web` extra adds FastAPI/Uvicorn; test and static-analysis dependencies are in the `dev` group. Frontend dependencies use npm and `frontend/package-lock.json` as their only lock authority. DECIMER is an external Python 3.10 runtime boundary and is not part of the Python 3.12 application lock.
- Public contract: the `x-patentsar` CLI, `PATENTSAR_*` configuration variables and documented output files; Web API uses an independently versioned `patentsar.web-api` v1 contract. A Web result/review never overrides deterministic QA.
- Runtime state: operator-selected output paths, `PATENTSAR_STATE_DIR`, or the XDG state directory; runtime data never belongs in source or `site-packages`.
- Table ownership: shared `core/table_geometry.py` and `table_cells.py` supply observations to separate biology and numbered-structure consumers; recognized pages cannot enter competing generic parsers. Raw observation inheritance is a validated input to the sole CLI chain, never a second acceptance/recovery authority.
- Spatial ownership: explicit catalog scopes separate proved subset reprints from conflicting complete catalogs; exact prefixed captions preserve letter suffixes. Complete confirmed coverage bypasses generic repair, with one artifact writer and the existing strict downstream QA authority. The binder implementation epoch is part of its stage fingerprint.
- Stage ownership: `application/pipeline.py` owns one eight-stage registry with an explicit `PipelineContext`; stage policies/cache helpers are single authorities, not private aliases in CLI commands. `core/structure_binder.py` owns source partitioning, including recognized-but-withheld I-series cells, and delegates to acyclic responsibility modules before one artifact writer.
- Recognition ownership: one verified printed-DECIMER adapter is shared by formal extraction, research and environment probes. The external runtime has bounded JSONL transport, serial model inference, CPU/resource limits and exact-content cache identity; no hand-drawn or single-image fallback is used in production.
- Attempt ownership: every new/resumed job has its own output root; bounded checkpoint transport and sealed terminal stage history do not rewrite old jobs. Legacy shared-directory stage history is explicitly unavailable. Progress, recognition and manual-count DTO additions retain API v1 and workspace SQLite v1.
- Live results: completed checkpoints project into the existing read model while the owned CLI runs. The UI keys results by job ID and stage revision; provisional counts never imply acceptance.
- Generated output: wheels and source archives are created under ignored `dist/` and must be reproducible from an identified clean revision. `frontend/dist` is copied by `tools/build_frontend.py` into ignored `src/patent_sar_extractor/web/static` for wheel packaging; a content manifest checks exact generated assets and protects modified files.
- Vendored/model assets: none. DECIMER and OCR model assets are externally installed and retain their upstream licenses.
- Branch/delivery policy: task branch and isolated worktree for concurrent work; `main` is the integration and deployment authority. Every task-related PR must be merged, the exact merged revision deployed, and the affected installed paths verified before completion. Pushing a branch alone is not delivery.
- Verification policy: map the exact diff and affected consumers to focused regressions, static checks, wheel-content audit, installed-wheel identity/health and applicable real-browser/API smoke. Global test suites require explicit user authorization. Existing required checks and branch protections must not be disabled or bypassed; an unrun check is never reported as passed. Dependency changes additionally require frozen sync and dependency validation.
- Rollback: stop the new process and restore the previous executable/path; never mutate existing run directories during rollback.
- Visual authority: `frontend/src/styles/tokens.css`; component CSS consumes one warm-ivory/stone/ink/terracotta palette. X-PatentSAR remains independent, with no copied third-party trademarks, proprietary fonts or product assets.
- External molecular runtime: ADMET-AI 2.0.1/Chemprop/PyTorch CPU lives in an independently installed Python 3.12 environment. Packaged `defaults/environments/admet-cpu-requirements.txt` pins the complete external boundary with hashes; it does not compete with the main application's `uv.lock`. `tools/prepare_admet_models.py` and the installed model preparation library share one verification authority. The model inventory, inference cache and actual scientific inputs remain outside Git.
- Task presentation: one full task input page invokes the same upload and durable CLI queue; source-only `web/result_queries.py` owns result presentation. `web/analysis*` and dedicated workers own research inference/summary, with a separate rebuildable cache schema. They have no formal-output authority.
- Environment control: the existing `#/settings` route is the only environment management page. `web/environment_models.py` defines the additive API-v1 DTOs; `environment_specs.py` owns the six fixed CPU components. Separate private environment SQLite v1 stores settings/operations, with no core workspace migration. Configuration publication reuses `env_paths.local.yaml`; process lifecycle reuses the same owned subprocess carrier. Approved storage and models are external, with no arbitrary installation API.
- Environment recipe provenance: `defaults/environments/base-requirements.txt` and `base-runtime.json` are derived by `tools/build_environment_resources.py` from the sole application `uv.lock`; CI requires `--check`. `decimer-inputs.txt` documents the external Python 3.10 seed, while `decimer-requirements.txt` and the ADMET CPU recipe pin their separate scientific boundaries. `decimer-models.json` owns reviewed model content digests; wheel audit requires all six text resources and rejects scientific model binaries.
- Recovery baseline: commit `186fd0ef4d923104dcd4754282bb434ba9758b34` preserves the recovered, tested core and Apache-2.0 branding/API contract. Source archives and historical data remain external on E. The authorized open-source remote is `https://github.com/Victor-Xu-1/X-PatentSAR`; publication is validated through its actual visibility, exact remote revision and CI, not inferred from repository creation. The product and repository use the exact display name `X-PatentSAR`; Python distribution and CLI identifiers are the normalized technical name `x-patentsar`.

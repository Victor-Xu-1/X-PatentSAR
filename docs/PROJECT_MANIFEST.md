# Project governance manifest

- Independent SAR ownership: `core/sar` is the sole strict fixed-graph/stereo/port and raw-measurement comparison domain; `web/sar` is the sole independent snapshot/import/region/job/result authority and private SQLite v1. `frontend/src/features/sar` consumes its additive authenticated API-v1 contracts and the existing locale/token system. The user explicitly starts project snapshots or mapped CSV tasks; no entry/navigation automatically writes, starts inference, adds an extraction stage, modifies original/correction/QA data or replaces current Lead nominations. The existing bounded subprocess gains only an optional pre-input durable-ownership hook; one shared analysis lease protects model-free bounded SAR execution and verified recovery. Exact snapshot atom order, source/input/algorithm fingerprints and sealed chunks prevent guessed/stale reuse. Storage follows existing upload/result settings; SAR fault/readiness is independent of core extraction. `contracts.py` owns independent SAR database/report/engine versions. No extra dependency authority, scientific model, local LLM, third-party transmission, global test or private patent publication is added.

- Interface-language ownership: `frontend/src/i18n/languages.ts` owns supported locales and the English default; `locale.ts` owns the one browser preference/subscription; modular message catalogs have one conflict-checked assembly/formatting authority. Chinese and English are mandatory and additional languages extend the same registry/catalog. React locale changes do not remount workspaces, dialogs or drawings, rewrite raw source/chemistry/value/user data, change route/filter IDs, call a model/API, or create a second backend settings/pipeline. UI error source descriptors remain redisplayable after a switch. Product releases follow the PR policy; scientific epochs and API/database contracts remain unchanged.

- Bounded repair/recovery ownership: `core/activity_coverage.py` inventories original coordinate/text regions and otherwise uncovered classified seeds independently of returned rows; activity epoch7 and QA schema4 prevent partial rows from masking missing tables. One existing writer/QA owns publication and acceptance. `integrations/llm/api_failures.py`, `job_health.py` and `credential_authorization.py` separate safe wire faults, same-logical-budget attempt circuit state and revocable GUI credential references. New context v2 does not duplicate GUI keys; explicit idle-job renewal preserves semantics, original, snapshot and spent calls. The sole HTTP/cache client validates before caching and revalidates/precisely evicts on read. Web `llm_job_recovery.py` owns additive v1 health/renewal metadata; thin routes retain session/CSRF/visibility and active/config/budget locks. Frontend recovery remains on demand and never automatically resumes, invents counts or exposes raw provider failures. No local LLM, extra parser/writer, new model service, whole-PDF transmission, numerical/chemistry rewrite or acceptance bypass is introduced.

- History-removal ownership: one recoverable history service and additive private visibility records own daily-page deletion/restore for projects, jobs, owned saved exports and terminal environment operations. Immutable artifacts, audit, internal producer/checkpoint ancestry and acceptance remain independent. Normal source/write routes recheck visibility, mutations use revision and active/ownership gates; project removal respects the existing analysis lease. Child restoration requires a visible parent and preserves separate removals. Bounded native export discovery cannot adopt arbitrary/symlink/imported paths. UI confirmation states retained bytes/no disk reclamation. No permanent purge, uninstall, retention scheduler, model call, audit-trigger weakening or competing deletion chain is introduced. Product releases follow the PR policy; APIv1/private SQLitev1 stay unchanged.

- Lead ownership: small `web/lead_*` modules own reviewed cached ADMET evidence, exact-context activity scoring, molecular diversity and one rebuildable project-wide nomination packet. The existing research worker invokes this bounded CPU tail after model release; completion checks current full pool/producer evidence. `ResultQueries` attaches shared marks before filters/paging/export; UI never scores or selects. Audited value edits re-evaluate without inference; graph changes use the existing targeted task. Unknown activity or unproved/rejected chemistry is never padded into target-eight candidates. Original artifacts/QA/audit, API v1 and workspace schema v1 remain unchanged. The additive private `lead_selections` table is a rebuildable research cache with source/graph/value/policy fingerprints and CAS, not an acceptance authority.

- General-format parsing ownership: classifier2, binder8 and activity7 are implementation epochs in `contracts.py`, not product/API/schema releases. `heading_evidence.py` proves original heading/standalone-diagram ownership; `structure_table_headers.py` proves wide/reordered physical column roles. `activity_header_metrics.py` and `activity_grid_cells.py` preserve raw multiline headers, all physical columns and units without patent-specific maps. Shared upright coordinate/cell OCR, explicit missing markers and independent crop proof replace permissive text repair; old derived stages are not relabelled. Product release numbering follows the PR policy.
- Optional evidence-interface ownership: `integrations/llm/evidence_protocol.py` defines supplied candidate/reference selection, `evidence_resolution.py` owns default-OFF consent and bounded serial budget over the sole existing LLM client/cache, and `application/evidence_review.py` is one post-bind/activity column-review consumer. Complete required refs, original SHA and current source context are rechecked. Private `evidence_resolution_review.json` is non-authoritative; no automatic chemistry/cell rewrite, extra recognition service, whole-PDF submission or QA promotion. Heading/table candidate protocols do not silently acquire production acceptance authority.

- Configurable-location ownership: the existing environment settings API/revision and private SQLite v1 own install, upload and result destinations in one transaction. Additive `file_settings`/`file_roots` retain bounded current/history mappings, not a new configuration database or API. `location_records.py`, `data_location_policy.py`, `workspace_locations.py` separate persistence, native-prefix ownership and current/historical resolution. Old relative PDFs and old runs stay in place; new absolute originals require a registered private upload root. Attempt/checkpoint and prediction consumers share those roots; explicit immutable `RunSpec.workspace_root` replaces parent-directory inference for new jobs. `saved_exports.py` persists the existing export bytes atomically without another renderer; native results and new export copies use the selected result root, while browser Save As is outside server control. API v1 and scientific contracts remain unchanged.

- Complete-environment invariant: after the application starts, users deploy all default-workflow dependencies with one software-owned complete plan, including ADMET and models, not a sequence of manually assembled installations. The sole component specs derive API-v1 `setup_component_ids`; one existing durable install operation rechecks/reuses, installs deficient components and activates only after all checks pass. Root/error probes never imply missing content. The primary page contains readiness, complete setup and active progress only. Necessary component and location settings live in one separate details dialog; logs/history persist behind the operator API, not in daily UI. Legacy presets remain only API compatibility metadata. WSL/system/GPU/application bootstrap is explicitly outside this scientific-environment setup. Product release numbering follows the PR policy.

- Environment-status ownership: `environment_catalog.py` projects configured path presence, exact-identity current checks and same-path history from at most six existing JSON reports. Per-component timestamps are additive; API v1 and environment SQLite v1 stay unchanged. The manager captures a stable snapshot and rejects changed inspection publication. Metadata GET never loads SDKs, downloads or installs; UI ready/pending/repair actions reuse the existing durable operation and consent boundary.

- Activity-rank presentation: the same `ActivityColumnCatalog` owns full-project histograms before filtering/pagination. `activity_rank_values.py`, `activity_ranking.py` and `activity_rank_models.py` separate exact values/conventions, bounded tied-tercile selection and additive API-v1 presentation DTOs. Only visible rows receive aligned read-only scores; empty raw fields are excluded, preserving fingerprints/exports. The frontend only consumes scores/cutoffs. No extra query, PDF/model, persisted ranking, schema/product bump or formal acceptance path is introduced.

- Product/repository identity: `x-patentsar` / X-PatentSAR; current stable E-drive WSL source path `/srv/wsl/projects/patent-sar-extractor` (preserved through branding). Internal Python namespace remains `patent_sar_extractor`; it is not a competing product identity.
- Product version authority: `src/patent_sar_extractor/contracts.py`; merged-PR numbering with patch 0-99 and minor 0-9; see `OPERATIONS.md`; release tags use `vMAJOR.MINOR.PATCH`.
- Internal contract authority: the same `contracts.py` file separately owns pipeline `patentsar.structure-led` `3.0.0`, ruleset `2.1.1`, stage implementation epochs and artifact/cache/observation schema identities. SMILES schema v2 uses the complete proved printed-ID catalog for formal ordered associations; unproved source observations remain review-only. Older contracts are not retagged; product release numbering follows the PR policy.
- Supported source roots: `src/patent_sar_extractor`, `frontend`, `tools`, `examples`, `docs`, `tests`, `.github` and documented root metadata/launch files, including Apache-2.0 `LICENSE` and attribution `NOTICE`. `tools` owns reproducible build/packaging checks, not extraction logic.
- Dependency authority: `pyproject.toml` plus generated `uv.lock`; uv 0.11.31 is the verified lock/sync tool, matching CI. The `web` extra adds FastAPI/Uvicorn; test and static-analysis dependencies are in the `dev` group. Frontend dependencies use npm and `frontend/package-lock.json` as their only lock authority. DECIMER is an external Python 3.10 runtime boundary and is not part of the Python 3.12 application lock.
- Public contract: the `x-patentsar` CLI, `PATENTSAR_*` configuration variables and documented output files; Web API uses an independently versioned `patentsar.web-api` v1 contract. A Web result/review never overrides deterministic QA.
- Runtime state: operator-selected output paths, `PATENTSAR_STATE_DIR`, or the XDG state directory; runtime data never belongs in source or `site-packages`.
- Table ownership: shared `core/table_geometry.py` and `table_cells.py` supply observations to separate biology and numbered-structure consumers; recognized pages cannot enter competing generic parsers. Raw observation inheritance is a validated input to the sole CLI chain, never a second acceptance/recovery authority.
- External API ownership: existing operator `llm.local.yaml` is the sole provider/policy authority; redacted revisioned settings and a separately consented synthetic test use the existing Web security boundary. All LLM work is API-only through three wire adapters, one bounded public-HTTPS carrier, private content cache and persistent serial quota. Immutable logical-job snapshots survive resume; GUI OFF/consent/key revocation blocks further disclosure. Activity epoch7 admits only revalidated original ID-column candidates to the same cell parser/writer; post-activity/source-led QA suggestions never override acceptance. Removed whole-page VLM, unbounded/free-form/key-only QA and batch callers are not competing paths. No local LLM runtime/weights/dependency, arbitrary template, whole-PDF upload, fabricated chemistry/value or extra acceptance authority is introduced.
- Checkpoint-order ownership: the artifact map derives from `CORE_STAGE_ORDER`; no legacy activity-first copy loop is retained. Window control v2 uses bounded owned input fingerprints and immediate worker-side chunk sealing via the existing manifest authority. The parent verifies, not rewrites, successful batch proofs; incomplete old metadata, acceptance and history are not promoted.
- Spatial ownership: explicit catalog scopes separate proved subset reprints from conflicting complete catalogs; exact prefixed captions preserve letter suffixes. Complete confirmed coverage bypasses generic repair, with one artifact writer and the existing strict downstream QA authority. The binder implementation epoch is part of its stage fingerprint.
- Visible-label ownership: epoch8 observations require actual original-PDF SHA-256, crop SHA-256 and exact page/box identity. `visible_label_cache.py` and `binding_observations.py` preserve optional identity-checked transport/refinement. Fresh native/shared page, cell and heading reads are the sole current observation path; the unused PaddleX batch/crop producer, private word-coordinate provider and private RapidOCR/Tesseract fallbacks are removed. Atomic writes preserve old bytes on failure; no missing cache starts another provider. Compatibility imports only re-export the retained transport implementation.
- Distribution ownership: `tools/wheel_sources.py` defines the current tracked source plus verified frontend inventory for both `build_wheel.py` and `audit_wheel.py`. Every wheel is built in a fresh snapshot; old build directories and untracked user files remain untouched. Auditing rejects extra/deleted modules, missing current files and changed source bytes. Runtime state and scientific acceptance are unchanged; product releases follow the PR policy.
- Phase-resource ownership: after the sequential binding handler returns, `core/phase_resources.py` releases this worker's shared/profiler/thread-local OCR references, trims the process-local PDF store and supported allocator, and records measured before/after RSS. It does not initialize engines, delete page caches, stop processes, touch other tasks or lower the bounded model-memory admission budget. Cached and failed binding exits use the same handoff.
- Observation completion: the source coordinator uses the same internal `--continue-on-scientific-errors` contract for OCSR and final export. Only current source scope with complete exact printed-ID/image coverage can use the OCSR completion mode; diagnostic/limited/unbound inputs cannot. Default standalone OCSR still rejects non-clean output. Complete findings remain rejected, preserve the shared failure marker, and flow to final QA so eligible records can enter the qualified research phase. Infrastructure exceptions and incomplete/misassigned observations still abort. Raw prediction caches remain identity-checked and independent; no algorithm/epoch/model/API/product version changes.
- Review-workbook ownership: the main Excel sheet retains every proved identifier in source-catalog order, including original images and optional activity for unqualified chemistry. Only qualified chemistry maps populate molecular fields; pending rows stay blank there and carry a recognition-status column. SDF selection remains qualified-only and formal QA unchanged. The export receipt reports workbook IDs/review IDs separately from qualified molecular export IDs; no uncertain SMILES or placeholder molecule is promoted.
- Verification ownership: the checked-in `.github/verification_scope.json` declares exact base/changed paths and bounded named Python/frontend/browser consumers. Small pure-validator/runner tools reject stale, unsafe, wildcard, overlapping or whole-inventory plans; no discovery/default-all fallback exists. Empty frontend/browser selections do not start their test engines. CI preserves builds/resources/fresh-wheel audit. - Recognition ownership: one verified printed-DECIMER adapter is shared by formal extraction, research and environment probes. - QA ownership: `qa_inputs.py` gathers one immutable pass context; `qa_sources.py` and `qa_files.py` inspect source and output evidence; `qa_checks.py` owns source/recognition/output gates; `qa_report.py` only orchestrates and presents the report. Historical v1/v2 remain readable but cannot pass the current formal gate. Upstream classifier/locator/segment/binder/activity epochs stay unchanged for this source-risk-only correction; validated upstream checkpoints and exact raw observations may be reused, never historical acceptance. - Attempt ownership: every new/resumed job has its own output root; bounded checkpoint transport and sealed terminal stage history do not rewrite old jobs. Legacy shared-directory stage history is explicitly unavailable. Progress, recognition and manual-count DTO additions retain API v1 and workspace SQLite v1.
- Recovery ownership: bounded `process_identity.py` and the existing supervisor own same-boot cleanup/previous-kernel absence proof. `job_recovery.py` archives identity before compare-and-set recovery publication and rechecks blocked interruptions at startup. `job_preparation.py` owns durable queued readiness/bounded inactive source ancestry, with cancellable copying outside the writer. `checkpoint_chunks.py` only adapts completed batches into the existing copy/fingerprint authority, never a second cache/acceptance path. Unchanged identity/idle polling is read-only; projection encoding precedes writes. Additive private preparation fields/receipts retain independent release numbering, API v1, SQLite v1 and immutable history/QA; invalid/foreign guards remain fail closed.
- Projection publication: `WorkspaceService.refresh` binds an artifact view to its observed run root; `Store.snapshot` checks the expected root and original SHA inside the writer before any compound deletion/publication. A stale read cannot restore a prior attempt's rows/acceptance after new enqueue. No artifact, schema or acceptance authority changes.

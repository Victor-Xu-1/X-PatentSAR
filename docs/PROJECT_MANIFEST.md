# Project governance manifest

- Core exploration context ownership: `StudyNetwork` chooses references from
  the complete current inventory independently of gallery filtering. Only
  deliberate different-core selection resets a site. Matrix-specific palette
  geometry in `sar-matrix.css` keeps all entries and native drawing coordinates;
  the shared `useInlineSelection` explicitly enables local two-axis reveal for
  RegionLegend, preserving inline defaults elsewhere. No new cache/queue/model,
  matcher/proof/source/epoch/API/schema or task-specific branch is introduced.

- Property-number presentation ownership: `propertyDelta.ts` is the shared
  matrix/pair display authority. A source/status-bound native continuous-property
  machine-precision guard labels approximation, retaining the full raw delta.
  It cannot alter API/storage values, activity rules, outcomes, ranking, count
  metrics, imported/manual/model evidence or scientific engine identity.

- Browser startup ownership: `tools/wait_browser_server.py` validates a bounded
  already-started owned PID/loopback HTTP schema/exact installed version. CI keeps
  service lifecycle ownership; this tool cannot start/stop it or run science.
  `frontend/e2e/matrix-reading.ts` verifies completed native column geometry and
  physical ID hit targets, without changing product motion, graph or result data.

- Series-reading ownership: `coreChoices.ts` is presentation-only core inventory
  and alternate view order over complete published membership; no new drug score,
  region pruning or original-label rewrite. `matrixScrolling.ts` owns bounded
  actual-column navigation through the shared focus/motion/overflow path.
  `preview_properties.py` supplies shared pair/matrix origin-aware arithmetic and
  isolated typed status. Raw values, captures, graph/pair proofs and scientific
  engine/checkpoint identity stay intact; unknown/different provenance cannot
  manufacture a delta. No new producer, model, queue, cache, schema or dependency.

- Matrix ownership: `preview_source.py` prepares a single immutable report/input;
  `study_preview.verified_preview` remains the unique strict member/pair/value
  proof. `study_matrix.py` and isolated `matrix_models.py` project at most6
  same-reference candidates, completely refused above8MiB or on any invalid
  member. `matrix_drawing.py` reuses original-atom native coordinates, existing
  connected-core alignment, stereo/graph roundtrip and one full matrix camera.
  Modular frontend matrix components reuse member paging, source/focus/locale
  authorities, keep raw supporting data and captured predictions separate,
  and never infer missing PK, activity, properties or confidence. No new
  dependency, queue, schema, scientific epoch, archive edit or global suite.

- Whole-trash ownership: existing history visibility/lifecycle/lease gates remain
  sole authority. `history_trash_plan.py` prepares a bounded complete four-kind
  snapshot, not a page/category sample. `history_purge.py` publishes all permanent
  UI markers and one exact-request receipt atomically in the workspace writer;
  environment history attaches that private control read-only. A short shared
  history guard serializes restore/delete/clear. Small `history_asset_*` modules
  inventory exact native first-party files, retained project/checkpoint/SAR
  references and a sealed finite cleanup journal; `history_file_*` owns streaming
  fingerprints and exclusive kernel open-file protection. Only proved unreferenced
  originals/products are removed by no-replace quarantine/exact unlink and empty
  owned-directory rmdir, never a broad recursive delete. Imported, referenced,
  linked, busy or unverified assets, audit/source rows, caches and shared installed
  environments remain. Pending cleanup requires explicit same-request resume;
  reads/startup cannot replay. Cleared audit metadata no longer consumes ordinary
  quotas. Additive private tables retain schema1; no new queue/model/provider,
  scientific acceptance change or global test is introduced.

- Paired-layout ownership: `web/sar/preview_alignment.py` and `preview_drawing.py`
  and `preview_geometry.py` own only validated comparison coordinates/shared
  camera and native acute-fold safety. Connected fixed-core alignment is distinct
  from whole-background alignment for disconnected linker ends. The existing strict
  matcher remains sole admission authority; bounded equivalent embeddings are
  rechecked through its retained graph/ports/stereo primitives, with deterministic
  source-index presentation choice rather than a new chemical atom identity.
  Isolated preview DTOs and the existing `StudyImage`/safe SVG/focus path consume
  source-bound paired vectors. Native failures are explicit, redraw identity is
  checked, and no original atom/structure/measurement/producer is rewritten. No
  scientific engine hash/epoch, schema, queue, model, dependency or cache changes.

- Full-preview ownership: the existing strict preview and region/changes page
  authorities remain sole acceptance/member paths. `preview_records.py` provides
  only exact-source unselected-reading projection through isolated preview DTOs;
  frontend validates optional legacy-compatible data and keeps source values
  separate from analyzed conclusions. No inferred supporting delta/rank/context,
  new matcher/queue/store/model, captured-model change or scientific epoch bump.

- CSV-default ownership: `csv_mapping_rules.py` is the only header-role suggestion
  authority; `csv_preview_models.py` isolates bounded additive intake metadata.
  Frontend consumes typed suggestions rather than running another header matcher.
  Known metadata/physchem and explicitly declared captured predictions are
  prefilled; unknown/duplicate roles stay explicit. No numeric-sample heuristic,
  silent endpoint prefix, value/unit rewrite, new import/storage/queue/model,
  schema migration or scientific engine/checkpoint change is introduced.

- Indicator-default ownership: `web/indicator_conventions.py` supplies numeric
  polarity through the retained `activity_rank_values.rank_direction` interface.
  SAR `indicator_policy.py` projects bounded exact-context and unanimous metric
  defaults; isolated `indicator_models.py` extends only the profile read view.
  Both setup forms share one typed default display and keep manual controls only
  for unknown/conflicting endpoints. New admissions recheck known polarity after
  existing request replay lookup. Lead safety/desirability guards, source values,
  grade definitions, engine identity and archived inputs/results stay independent.
  Its rebuildable cache fingerprints the shared installed direction code and
  refuses old-rule nominations without read-side recalculation or inference.
  No new queue, database, dependency, inference or acceptance authority is added.

- SAR interval-order authority: `core/sar/values.py` supplies one exact numeric
  separation proof to pair statistics and Pareto ordering. Engine9/private input3

  New admissions/workers/parent publication require the current schema and
  candidate policy; old completed input2 has only a read adapter for captured
  gap-only semantics. Raw archives, graph matching, queues and environments are
  unchanged. Independent interval/endpoint inputs and full native publication
  checks must cover this shared rule, not one patent's expected result.

- Measurement-unit authority: engine10/input4 introduced `core/sar/measurements.py` for

  reference/study admissions, for CSV and project snapshots. Statistical values,
  potency bands, charts, row sorting and preview deltas share the same parser.
  Old input2/3 reads keep their captured parser semantics; no caller-facing unit
  override or alternative science path is introduced.

- Activity-scale authority: engine11/input5 use `core/potency_axes.py` with the

  all consumers carry its `negative_log_molar` basis. The shared immutable
  analysis preparation may derive unit1 from a known pActivity name, never from
  other rows or unknown log notation. Old input2/3/4 keep captured log-tier policy.
  No percentage cutoff, fifth-anchor fallback or page-relative rank is added.

- Single-site discovery ownership: SAR engine11 uses `core/sar/discovery.py` as

  dependency. `StudyNetwork`/`NetworkBranches` reuse current atom maps, drawings,

  `hydrogen.py` owns source-preserving one-ordinary-H views for the same matcher

  `cut_blocks.py` prunes impossible cross-block topology, not accepted chemistry.
  `fragment_graphs.py` owns explicitly labelled aromatic subgraphs; their nullable
  molecule SMILES cannot masquerade as an eligible compound. `site_reduction.py`
  uses the SAME full proof before removing nested same-pool automatic duplicates;
  all budgets stay unchanged. `prepared_graphs.py` owns one job-local bounded
  exact-source preparation pool; publication/preview recheck graph fields and
  no persisted result cache, new queue/model/dependency or original rewrite exists.
  `regions.py` owns exact prepared adjacency/port inventories; reference ports
  and at most64 per-comparison remainder topologies are reused, not embeddings
  or scientific results. Every full mapping retains its own anchor/stereo proof.
  Preparation changes keep graph semantics but change its source-bound hash;
  old unfinished work must not be relabelled or resumed with that new hash.

# X-PatentSAR architecture

## Responsive checkpoint preparation

The extraction queue reserves one durable attempt before returning its queued
response. Its existing single consumer prepares verified source checkpoints
outside the HTTP request and outside the SQLite writer transaction. The
producer cannot claim that attempt until its preparation is ready. Original
source ownership is rechecked at preparation time, while cancellation and
shutdown retain their own terminal state. Interrupted preparation can be
resumed from its declared original parent. A verified resume-parent identity
allows the interface to reconcile an uncertain submission without replaying a
write or inferring success from unrelated tasks.

## Raster title ink attached to original ruling

When retained title pixels are connected to a proved original table rule, the
system keeps the entire original pixel evidence and records an explicit
`crossing_title_ruling_ink` refusal. The caption role remains unresolved and
replayable; neither the attached stroke nor the rule is erased to infer a
title. Malformed ruling or pixel evidence remains invalid, not an uncertainty
that can admit a structure. Downstream declaration coverage continues to
withhold unsupported structures and reports the original title for review.
Binder and binding artifact epochs advance; old original observations and manual
revisions remain unchanged and require current-proof evaluation before reuse.

## Original catalogue frame association

Declaration capture retains the complete original grid inventory, including
duplicate observations, so existing geometric evidence remains replayable. It
associates an exactly repeated frame with its caption scope once. Duplicate
outer frames with different internal grid axes remain an explicit error; no
source geometry, role or identifier is selected by guesswork.
The binder epoch and binding artifact schema are advanced for the changed
catalogue-role semantics. Historical bindings are not retagged; existing
source and manual-audit history remain available for review. The activity
checkpoint depends on the binding artifact, so its reuse follows the new
binding identity rather than replacing raw observations.

## Reference and comparator catalogue roles

A qualified catalogue heading that explicitly describes reference, control,
comparator or comparative compounds/examples is not sufficient evidence that
those entries are this patent's final products. Its source role is retained as
a conflict for review, including mixed product/reference headings; it is not
silently excluded as an intermediate or promoted as an accepted product.
Unnumbered category headings still nominate source pages. Changes in this role
must invalidate affected derived proofs and preserve historical source and
manual revisions; earlier role decisions are not silently rewritten.

## A completed Lead tail does not certify a rejected core

The existing job stage is a producer observation, not proof that candidate
selection is valid. `reviewedCoreStage` derives a review-only presentation for
an explicitly core-rejected completed Lead tail, using the same rejection gate
as the other core stages. Task details and workflow groups show that the tail
executed while core acceptance failed; tooltips direct candidate eligibility to
the actual result. The review icon replaces the green completion icon without
changing the recorded status, progress, selection, scientific inputs or policy.
Missing/technical-error history and accepted/independent runs retain their own
recorded states; no candidate count is invented for historical data.

## Staggered physical catalogues retain one complete source family

rederives the parallel peers from it. `title_family_geometry` gives each physical
column its own preceding-frame fence; the saved title source covers the complete
family envelope, not the intersection of successful local crops. Earlier body
cells and title regions can be partitioned only by actual closed frames with
paired original rule pixels. Narrow frames cannot hide exterior ink. Crossing,
competing, missing or over-budget owners refuse rather than choosing a neighbour.
Native words and complete glyph operations remain conserved. The same source
contract supports native, outlined and raster staggered catalogue controls;
logical parallel headers and paired raster-blankness proof remain separate gaps.

`source_paint_paths` adapts original PDF form paint ownership in the existing
paint view. Consistent engine sequences are kept. If embedded forms disrupt
sequence identities, only a unique exact single axial-stroke envelope may map;
duplicate/complex/unmapped paints remain unknown. No nearest-box or sequence

## Resource lifecycle

- `page_ocr_execution` owns bounded original page indices, payload/coordinate
  shapes and source coverage. At most one request per OCR worker is pending;
  a failure stops new requests and drains already-owned successful observations
  into the existing atomic checkpoint writer. Native fast paths remain model-free.
  `page_ocr_protocol` validates the one-image transport; missing/ambiguous image
  envelopes or unequal text/box arrays fail explicitly, never truncate or fall
  back to a native footer. Valid empty observations remain distinct from failure.
  `page_ocr_cache` is the sole backend facade/cache writer; build and update share
  the same reader. Known source extension fields and inherited producer receipts
  survive updates. Classification requires all original pages, and checkpoint
  reuse rechecks original PDF identity and complete source before declaring reuse.
  Classifier epoch5 changes derived execution compatibility; raw observation2 and
  independent binding/activity/chemistry contracts remain unchanged. These bounds
  do not prove detection recall, original value correctness or chemical identity.

- One task owns its active heavy phase. Existing analysis lease prevents two
  owned inference consumers; no permanently resident parallel model servers.
- Before loading, bounded admission measures `MemAvailable`. Default model
  headroom is3072MiB, with at most110s waiting; an unavailable measurement or
  expired wait is explicit failure. No other application is stopped. The UI
  shows waiting only from live, owned, recent measured telemetry.
- Segmentation loads one verified model for at most three pending chunks
  (normally30pages, at most60); each completed chunk has its own immutable
  input/dependency checkpoint. A failed later chunk retains successful earlier
  chunks. The next window uses a fresh process, with no overlapping model.
  Internal window control v2 passes owned bounded fingerprint files. The worker
  verifies unchanged original/dependencies and seals each successful batch
  immediately using the sole manifest authority; the parent only verifies.
  Checkpoint transport follows the same `CORE_STAGE_ORDER`, not artifact-map
  declaration order. Unsealed old metadata is never retroactively approved.
- DECIMER recognition is serial with bounded preparation and an exact-image /
  exact-model raw cache. Healthy workers recycle after100observations or900s.
  Consecutive infrastructure starts are bounded; exhaustion aborts the batch
  rather than labeling every remaining molecule a recognition failure.
- ADMET reuses one task-owned CPU model for at most five50-molecule requests or
 150s between requests. Request JSON, stdout/stderr, owned descendants, RSS,
  CPU and wall time are bounded. Cleanup is verified before recycling or
  release; unverified ownership prevents further inference.
- Per-stage lifetimes are bounded by actual work and the queue's global task

  retries, alternative recognizers, fabricated outputs or relaxed QA.
